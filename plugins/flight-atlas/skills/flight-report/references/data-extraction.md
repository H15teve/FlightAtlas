# 从航旅纵横准备主 CSV 和辅助 XLS

本页是 Agent 操作说明。向用户提供[图文提取教程](../../../docs/data-extraction.md)，其中包含完整提示词和入口截图。

没有主 CSV 时先引导用户操作，不要求账号、验证码、Cookie，也不自行调用未公开的 APP 接口。可将用户提供的完整 CSV 文本保存为新的私人 UTF-8 文件；不得用演示数据或先前用户的行程代替。

## 用户操作

1. 航旅纵横内进入 **我 → 全部 → 特色服务 → 小横智能助手**。
2. 读取并提供本目录的 [extraction-prompt.txt](extraction-prompt.txt)，让用户完整粘贴给小横。19列固定来源规则和UTC时长校验是关键，不随意缩写。
3. 建议处理时保持亮屏，不离开页面；原作者遇到的中断问题不代表所有版本均相同。失败重发不等于应累计多份相同结果。
4. 将CSV代码块保存为UTF-8 .csv，只包含表头和数据行。输出截断时，从最后完整行之后续传；用日期、原航班号、起降三字码和表定出发共同定位，禁止重复表头，残缺行重新取得。用户也可直接提供多段CSV文本，由Agent在私人工作目录拼接、校验。
5. 校验实际已乘坐历史总数、每行19列、日期/代码/时长、疑似重叠批次，不把小横的自然语言保证当校验结果。总数可与APP已结束列表/可选XLS对照，但先确认记录范围相同；数量或续传锚点无法核实时，明确标为待核验候选，不宣称全量完成。

增量更新时读取[incremental-update.md](incremental-update.md)：只将提示词第一句话改成用户指定的起止日期范围，其他文字和19列要求不变。首句明确后文“全部历史行程”“全量”仅指该范围；核验本次范围的记录数，不与累计次数强行相等。先与用户本地历史匹配、解决冲突，再按全部历史制图。

显示时刻是各机场当地时间；提取提示词要求完整起降日期及历史时区（含夏令时）转UTC后计算时长。缺日期/跨日关系/时区时留空，不推测，也不按两个当地时刻相减或统一加24h。插件默认读取表中提供的实际时长，缺失才取该行表定时长；异常值需先核验。

提示词按作者要求仅修改两条时长规则，其余原文保留。字段原样输出优先：航班号/注册号/座位号可含数字和连字符，不因笼统的“字母列”描述删字符；缺值规则中的“留空”按`-`表示。若助手实际返回空格，检查并记录差异。19列本身不含完整到达日期和时区偏移，格式校验不能独立重算全部国际时长；需要时另请用户/小横提供相关航段的计算依据，存在私人审计中，不改列序。

## CSV优先，XLS仅作辅助

小横19列CSV为默认主要输入。APP的 **行程 → ⋯ → 导出航班行程** 生成的XLS可选，用于核对记录数、日期、原航班号、起降城市/时刻、里程。截图入口标为PRO专享，依账号/版本权限；没有XLS也可开始CSV流程。

![辅助XLS导出入口](../../../assets/tutorial/04-xls.png)

只读导入辅助XLS；客票号等个人列丢弃，不显示/发布。匹配原出发日期+原导出航班号+起降机场/城市，必要时加表定时刻；城市不能区分PEK/PKX等机场时保留歧义。共享航班改为已核验主号后仍用审计保留的原号匹配。营销航司不是实际承运人的证据。

不要拼接两份表增加航班；不要自动覆盖CSV。记录数、时间或里程差异交给用户核验，接受后另记私人修正依据；保留原文件哈希。原表里程默认指主CSV的公里值，不能静默替换成XLS值。用户明确授权合并新增航段是另一项操作，不由“辅助印证”推定。

只有XLS时先推荐提取CSV，再询问用户是否愿意使用缺少机型/注册号/实际时长等信息的兼容模式。不要声称XLS等价完整或为用户自动选择降级模式。缺素材/共享核验和其他决定仍按 [first-run.md](first-run.md) 处理。
